정책 템플릿

  • PUBLIC: 공개 자료, 일반 인덱싱 허용.
  • INTERNAL: 사내 열람만 허용, 외부 API 금지.
  • CONFIDENTIAL: 청크 암호화, 역할 기반 접근, 세션 단위 감사.
  • RESTRICTED: 마스킹/토큰화 필수, 교차 테넌트 검색 금지, 파인튜닝 금지 또는 비식별 전용.
  • TRADE_SECRET: 배합비, 공정 recipe, 설비 보정값, 소스코드 핵심 알고리즘 등 별도 카테고리.

문서 업로드 후 변환 파이프라인

  1. 업종(KSIC/NACE/NAICS)·문서유형·소스시스템 메타데이터 강제 입력
  2. OCR/파싱 단계에서 문단·표·이미지·서명·식별자 후보 추출
  3. 민감 엔티티 검출: 개인정보, PHI/PCI, 계좌·거래·진단·배합비·설비값
  4. 정책 엔진이 필드별 조치 결정: 삭제, 부분 마스킹, 범주화, 토큰화, 해시화
  5. 변환 후 chunk metadata 부여: industry, sensitivity, transform_action, lineage
  6. 임베딩/벡터화는 보안 등급별 별도 index 및 keyspace에 저장
  7. RAG 질의 시 OpenFGA/OPA 기반 필드·문서 단위 접근판정과 감사로그 기록

오픈소스 기반 보안 기술 스택

  • OCR/파싱: Tesseract, OCRmyPDF, Apache Tika, Unstructured, GROBID.
  • 민감정보 검출: Microsoft Presidio, spaCy, Hugging Face NER, 정규식 룰셋.
  • 가명화/변환: Presidio Anonymizer, custom tokenizer vault, Faker/합성데이터 파이프라인.
  • 정책 엔진: Open Policy Agent, Cedar, JSON Schema 기반 validation.
  • 권한 모델: OpenFGA, Keycloak/OIDC, document-level ABAC/RBAC.
  • 벡터/RAG: Qdrant, Weaviate, pgvector, LlamaIndex/LangChain, reranker 분리 배치.
  • 관측성: Langfuse, OpenTelemetry, Prometheus, Grafana.
  • 비밀관리: HashiCorp Vault, External Secrets Operator, KMS 연동.

권장 배치 아키텍처

  • ingestion worker와 retrieval worker를 분리하고, 민감 원문 저장소와 변환본 저장소를 이중화합니다.
  • vector DB는 민감도별 namespace 분리, customer-managed key, audit trail 활성화를 기본값으로 둡니다.
  • LLM gateway에서 외부 모델 호출 전 policy decision point를 통과시켜 RESTRICTED/TRADE_SECRET 청크의 유출을 차단합니다.
  • fine-tuning은 de-identified corpus와 synthetic augmentation 전용 파이프라인으로 분기합니다.

규정 준수 현황 시각화

운영 KPI 제안

  • 업종별 민감 엔티티 검출률
  • 문서 유형별 마스킹 적용률
  • 정책 예외 승인 건수와 만료율
  • 외부 모델 차단 요청 수
  • 고위험 청크 비중과 재색인 소요 시간
  • 재식별 키 접근 이벤트 수

산업분류 거버넌스 모델

KSIC를 canonical key로 두고 ISIC/NACE/NAICS를 매핑합니다. 문서에는 ksic_section, division, control_profile를 함께 저장합니다.

핵심 메타데이터

  • industry_code / doc_type / region
  • sensitivity_level / trade_secret_flag
  • transform_action / transform_rate
  • lineage / source_system / approval_id

제조 레시피 처리 예

예: “스프 A 배합비율 17.3%”는 그대로 저장하지 않고 recipe_component_ratio=RANGE_15_20 또는 recipe-secret-token으로 치환해 검색 가능성과 기밀성을 동시에 유지합니다.
